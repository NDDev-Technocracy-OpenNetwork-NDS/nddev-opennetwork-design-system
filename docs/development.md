# Development

Install the locked public dependencies with `just install`. The generator uses the DTCG 2025.10
community format and resolver with the Terrazzo parser. No private repository is a build input.

Edit canonical tokens and component definitions, then run `just generate`. The generator constructs
and validates a complete candidate, checks declared contrast pairs, takes a worktree lock and
publishes generated bytes with `generated/outputs.json`. It preserves foreign edits and detects
interrupted publications. `just check` verifies the candidate without repairing outputs.

`packages/` contains generated source distributions. `tokens/tokens.json` preserves the earlier
OpenNetwork color-view contract for launcher tools; the older Flutter class names are emitted from
the same model. `adapters/flutter` contains the authored Material application bindings and pubspec.
`tests/flutter` contains their acceptance tests; generated packages include those tests.

Source checks require no application build. Tests and toolchain checks run on execution hosts:

- `just test`: generator behavior, launcher contracts, Flutter analysis and real widget tests.
- `just test-browser`: reference components in four themes at narrow and wide viewports, axe checks,
  fonts, keyboard behavior, motion and layout. Renders are retained for visual review.
- `just platforms swift kotlin rust`: compile, lint and test each native source package.

The platform script uses verified SDK archives and digest-pinned official images. Generated fonts
are copied only after digest and metadata validation. Web consumers may serve `packages/web` as a
static directory, including `fonts/`; the reference has no remote font service dependency.

Changes affecting an application's package pin need its own qualification. A successful package
check does not establish native installation, device behavior or runtime integration in that app.
